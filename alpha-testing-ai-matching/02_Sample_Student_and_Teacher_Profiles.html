Sample Student and Teacher Profiles

Fictional documentation fixtures | No accounts inserted

These are proposed alpha records for coordinator preparation in an authorized non-production environment. Reference IDs such as T01 and S01 are document labels, not new database columns. Numeric IDs in the JSON are fixture IDs; map actual deployed IDs by confirmed account/course names.

Baseline conditions

All eight teachers are active and have zero assigned active, profile-complete students. All accept children unless a case explicitly changes that condition. No preferred schedule is supplied in the baseline. Teacher free text is exactly “English language educator.” before the structured profile block; this avoids unplanned keyword bonuses.

Teacher metadata: country Philippines; birthday 1990-06-15; role teacher. Student metadata: country Philippines; birthday 2000-01-15, so all baseline learners are adults. Emails ending in example.com are fictional identifiers, not usable credentials or inboxes. Use coordinator-provided unique disposable addresses for a save test.

Exact accepted assessment format

Enter integer scores from 1 to 5 in this order: Speaking & Pronunciation, Reading & Comprehension, Structure, Sentence / Grammar, Vocabulary. The application computes the level; do not manually choose a proficiency label.

The administrator form uses the labels above. Student-facing screens may use aliases such as Visual Learning, Guided Pace or Accelerated Pace for the same stored values. Pick course-available chips; do not use Others for the baseline.

Coordinator preparation notes

Prepare records separately; this package supplies no database insertion script. Specialization chips are limited by the union of teacher courses. Exact specializations must fit teacher_profiles.specialization; the current write path clamps its comma-joined text to 255 characters. Do not add degrees, certificates, teacher-proficiency fields or separate style/pace columns that the matching path does not read.
